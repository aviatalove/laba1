# README.md

OS Info Collector — Лабораторная работа 1

Кроссплатформенный скрипт на Python, который определяет текущую
операционную систему (Linux / macOS / Windows), собирает её базовые
параметры и сохраняет результат в файл `os_report.json`.

Работает одинаково на всех трёх платформах без изменения кода
и без установки дополнительных библиотек.

# Запуск

Требуется только Python 3.8+ (внешние зависимости не нужны).

python my_script.py

После запуска в текущей директории появится файл `os_report.json`.


# Пример вывода

В консоль выводится краткая сводка:

[+] OS: Linux | report -> os_report.json

На Windows это будет выглядеть так:

[+] OS: Windows | report -> os_report.json

На macOS:

[+] OS: macOS | report -> os_report.json


# Собираемые параметры

 1. `generated_at` — метка времени
- Локальное время формирования отчёта в формате ISO 8601
  (`2026-10-02T15:30:00`, без микросекунд).
- Нужна, чтобы понимать, на какой момент актуальны данные,
  и сравнивать несколько запусков между собой.

 2. `os` — операционная система
 Поле         Что показывает                  Пример        
 `family`     Семейство ОС                    `Linux`, `macOS`, `Windows`, `Unknown` 
 `release`    Версия ядра / сборки            `6.8.0-45-generic`, `23.5.0`, `10` 
 `arch`       Архитектура процессора          `x86_64`, `arm64`, `AMD64` 
 `python`     Версия интерпретатора Python    `3.12.3` 

 3. `hardware` — аппаратное обеспечение
 Поле          Что показывает 
 `cpu_count`   Количество логических ядер CPU (или `null`, если определить не удалось) 

 4. `environment` — окружение процесса
 Поле        Что показывает                Пример 
 `hostname`  Сетевое имя машины           `pc-lab` 
 `username`  Логин текущего пользователя  `student` 
 `home_dir`  Домашний каталог             `/home/student` 
 `cwd`       Текущая рабочая директория   `/home/student/lab1` 

 5. `filesystem` — файловая система
 Поле                Что показывает 
 `cwd_disk_free_gb`  Свободное место на разделе, где запущен скрипт (ГБ, 2 знака) 

Если раздел недоступен для чтения — значение будет `null`,
скрипт не завершится с ошибкой.

 6. `locale` — локаль и кодировки
 Поле        Что показывает                                Пример 
 `encoding`  Кодировка имён файлов в ОС                   `utf-8`, `mbcs` 
 `locale`    Значение переменной `LANG` или `LC_ALL`      `ru_RU.UTF-8`, `C`, `null` 

На Windows переменная `LANG` обычно не задана — тогда поле будет `null`.
Это нормальное поведение, а не ошибка.

    "python": "3.12.3"

    "home_dir": "/home/student",

  },

Файл читаемый: отступ в 2 пробела, кириллица сохраняется как есть.


# Используемые модули

Все модули — стандартные, входят в поставку Python.
Устанавливать через `pip` ничего не нужно.

 Модуль      Ключевые функции                                  Для чего 
 `platform`  `system`, `release`, `machine`, `python_version`  определяет семейство и версию ОС 
 `os`        `getcwd`, `cpu_count`, `expanduser`, `environ`    рабочая директория, CPU, home, локаль 
 `sys`       `getfilesystemencoding`                           кодировка имён файлов 
 `socket`    `gethostname`                                     сетевое имя хоста 
 `getpass`   `getuser`                                         логин текущего пользователя 
 `shutil`    `disk_usage`                                      свободное место на диске 
 `datetime`  `now().isoformat()`                               метка времени отчёта 
 `json`      `dump`                                            запись словаря в JSON-файл 


# Почему не использованы внешние модули

- `psutil` — умеет физические ядра, объём ОЗУ, uptime, но требует
  установки. Ради 2–3 дополнительных полей в учебном скрипте
  добавлять зависимость нерационально.
- `requests` — не нужен: скрипт никуда не отправляет данные.
- `subprocess` — формально стандартный, но он вызывает утилиты ОС,
  что прямо запрещено условием задачи.


# Ограничения

1. Никаких вызовов утилит ОС. Скрипт не использует `uname`, `wmic`,
   `systeminfo`, `df`, `whoami`, `hostname` и подобные команды.
   Вся информация собирается через API Python.

2. Только логические ядра CPU. `os.cpu_count()` возвращает число
   логических ядер (с учётом Hyper-Threading). Точное количество
   физических ядер стандартными средствами кроссплатформенно получить
   нельзя — для этого нужен `psutil`.

3. Свободное место только для одного раздела. Скрипт смотрит раздел,
   на котором лежит текущая рабочая директория, — не все диски системы.

4. Uptime не собирается. На Linux его можно прочитать из
   `/proc/uptime`, но на Windows / macOS аналога без внешних модулей нет —
   поэтому поле исключено для единообразия.

5. Поле `locale` может быть `null` на Windows — это норма, а не сбой.


# Проверка на разных ОС

 ОС       Что ожидать 
 Linux    `family: "Linux"`, `locale: "ru_RU.UTF-8"`, `cwd_disk_free_gb` — число 
 macOS    `family: "macOS"` (при этом `platform.system()` возвращает `"Darwin"`), `arch: "arm64"` на Apple Silicon 
 Windows  `family: "Windows"`, `locale: null`, `encoding: "utf-8"` или `"mbcs"` 


Скрипт не падает ни на одной из платформ — все потенциально
проблемные места обёрнуты в `try / except`.


# Как это работает (кратко)

1. `detect_os()` — определяет семейство ОС и её версию.
2. `collect()` — собирает все параметры в один словарь.
3. `main()` — вызывает `collect()`, пишет результат в `os_report.json`
   и выводит краткое сообщение в консоль.

Скрипт можно безопасно импортировать из другого кода — логика
запускается только при прямом вызове `python my_script.py`
(благодаря проверке `if __name__ == "__main__":`).
